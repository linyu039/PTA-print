# PTA 键盘输入模拟("百人star出AI版")

把一段代码按真人的打字节奏逐字符敲进 PTA 的代码编辑器。

页面收到的每一个字符都是 `isTrusted === true` 的真实键盘事件，全程不产生 `paste`，也不碰剪贴板。

## 为什么直接用 Ctrl+V 不行

PTA 在代码编辑器上挂了至少三层检测：

| 检测点 | 监听什么 | 直接粘贴会怎样 |
|---|---|---|
| `paste` 事件 | `document.addEventListener('paste')` | 触发，被记为「粘贴」 |
| `beforeinput` | `e.inputType === 'insertFromPaste'` | 触发，同上 |
| 输入节奏 | 记录每次 `input` 的时间戳 | 一次几百字，明显不像人 |

只要检测到其中任意一条，轻则标黄，重则整题判无效。

这个插件走的是第四条路 —— **浏览器的调试协议**。

## 原理

```
页面脚本 ──chrome.runtime──▶ 后台 ──chrome.debugger──▶ Chrome 内核
                                                        │
                                          Input.dispatchKeyEvent
                                                        ▼
                                              页面收到真实按键
```

关键点：

- `Input.dispatchKeyEvent` 是 Chrome 内核直接派发的事件，`isTrusted` 为 `true`。页面上的 JS 伪造不出来这个属性。
- 它走的是键盘输入通道，`beforeinput` 的 `inputType` 是 `insertText`，不是 `insertFromPaste`。
- 全程不触发 `paste` 事件 —— 因为没有粘贴动作发生。
- 中文、emoji 这类没有物理键的字符走 `Input.insertText`，它同样是 `isTrusted`、`inputType = insertText`，等价于输入法上屏。

## 安装

1. 打开 `chrome://extensions/`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选这个文件夹
4. 装好后到 `chrome://extensions/` 看一眼，确认版本是 `1.1.0`

## 使用

1. 打开 PTA 的代码提交页，等代码编辑器加载出来
2. 右下角会出现面板
3. **先把要提交的代码贴进面板的输入框**（这一步粘贴的是插件自己的框，PTA 看不到）
4. 用鼠标点一下 PTA 的代码区（让它拿到焦点）
5. 点「开始输入」
6. 等进度条跑完，确认代码无误，再点「提交本题作答」

输入过程中**不要切走标签页**，也不要点别的窗口 —— CDP 的键盘事件只送到当前前台页面。

## 面板上的按钮

| 按钮 | 作用 |
|---|---|
| 开始输入 | 逐字符敲进去，敲完自动逐行比对缩进 |
| 停止 | 立刻中断，已输入的部分保留 |
| 体检 | 打印页面结构：用的什么编辑器、选中的是哪个元素、当前多少字。装完第一次用先点这个 |
| 检视缩进 | 把编辑器和面板里的代码逐行对照，标出哪一行的缩进多了、少了，空格用 `·` 显示 |
| 修正缩进 | 按面板里的代码重新对齐每一行的行首缩进，不动正文 |
| 清空代码区 | 全选 + 删除，把编辑器清干净 |
| 节奏 | 循环切换 标准 / 快速 / 慢速 |

## 自动缩进：PTA 时有时无是怎么坑人的

PTA 的代码框在回车之后，有时候会照着上一行补一串空格，有时候一个都不补。还有极少数情况会反过来，把你打进去的行首空格吃掉。

这三种行为组合起来，同一段代码交两次可能得到三种不同的结果：

| 你打的 | PTA 干的 | 交上去的 |
|---|---|---|
| `    return 0`（4 空格） | 回车后自动补 4 个 | `        return 0`（8 个，缩进翻倍） |
| `        x = 1`（8 空格） | 一个都不补 | `x = 1`（0 个，缩进全丢） |
| `    y = 2`（4 空格） | 边打边吃掉行首空格 | `y = 2`（0 个） |

Python 对缩进敏感到一个空格都不能差，所以这三种情况全都会报 `IndentationError`。

**1.1.0 的处理方式是逐行校正**，不是打完再统一修：

```
每行开始
  ↓ 发回车
  ↓ 编辑器自动补了 N 个空格（可能 0 个，也可能照抄上一行）
  ↓ 读当前行真实的缩进
  ↓ 和目标缩进比：少了就补空格，多了就 Home → 右移 N 格 → Delete 掉多的
  ↓ 确认行首正好是目标个数的空格
  ↓ 才开始打这一行的正文
```

日志里会打 `编辑器自动补缩进 N 次，已当场校正 M 行`。

**1.1.2 又加了一道：每行打完当场验，不对就整行重写。**

**1.1.3 再往前挪一步：空格打完就量，多了当场删。**

**1.1.4 修回车被吞 —— 这是最要命的一个。**

CodeMirror 在补全、补括号的时候会把 Enter 吃掉。吞掉之后光标还停在原行，后面整行的内容全粘上去：

```
n //= 2  else:            ← else: 粘到上一行了
n = 3 * n + 1cnt += 1     ← cnt += 1 也粘了
```

行号一错位，后面每一行的缩进判断都跟着错，这就是你看到的「有的没打上」。

1.1.4 每次回车都验一次：按完读全文行数，没 +1 就是被吞了，再按一次，最多三次。日志会打 `⚠ 回车没生效（行数没变），再按一次`。

**同时把「整串一次插入」全撤了。** 1.1.2 / 1.1.3 为了让空格不出双份，用了 `Input.insertText` 一次插一整行。结果 PTA 把这个当成粘贴，弹「禁止复制粘贴」。

现在全部回到逐按键：`isTrusted === true`、`inputType = insertText`、零 `paste` 事件，和手敲没有区别。

那两个毛病靠「打完立刻量」解决，不靠换输入方式：

| 毛病 | 怎么治 |
|---|---|
| 空格变两个 | 打完量这一行长度，多出来的按 Backspace 删 |
| 回车被吞 | 打完数行数，没 +1 就再按 |
| 缩进补两次 | 回车后等编辑器落定再量，补完再量一次 |

行内的空格和行首的缩进是两个不同的问题。行首是「补几次」，行内是「插几个」：

| 现象 | 谁干的 | 1.1.3 怎么处理 |
|---|---|---|
| `if n % 2 == 0:` → `if  n  %  2  ==  0:` | 编辑器把一次空格插成两个 | 每打完一个空格立刻量这一行的长度，多出来的按 Backspace 删掉 |
| `    return 0` → `        return 0` | 自动缩进 + 我们补的，两头都补 | 回车后等编辑器落定再量，补完再量一次，多了删 |
| `    y = 2` → `y = 2` | 编辑器吃行首空格 | 补回去 |

空格这一步的做法是：

```
打空格前 → 记下这一行有多长
插入一个空格（走一次性 insertText，不是逐按键）
等 34ms 让编辑器落定
再量一次这一行 → 比刚才多 1 个字符是正常，多 2 个就是被插成两个了
多了就按 Backspace 回删，删到刚好
```

日志会打 `空格被插成 2 个，已回删 1 个`，结尾汇总 `有 N 个空格被编辑器插成两个，已当场回删`。

这样做的好处是**根本不依赖事后整行重写**。空格一多就当场纠回来，后面的字符接着往正确的位置打，不会错位。

缩进还有第二种翻车方式 —— 不是行首，是**行内**。打 `if n % 2 == 0:` 的时候，中间那几个空格可能被编辑器插成两个，变成 `if  n  %  2  ==  0:`。这行的报错信息还会把行号带偏，下面每一行跟着错一位或两位。

1.1.1 只能打完全篇再比对，那时候已经错了一片。1.1.2 改成**每一行打完立刻读回来比**：

```
打完一行
  ↓ 停 120ms 让编辑器落定
  ↓ 读这一行的完整内容
  ↓ 和期望行逐字符比
  ↓ 不一样 → 日志指出差异 → 整行重写
```

整行重写的做法是：`Ctrl+Home` 回到文档开头 → 走到这一行 → `Home` 两次到真正行首 → `Shift+End` 选中整行 → `Delete` 删掉 → **一次性插入整行**。

最后一步是关键。不用逐字符重打，因为逐字符会再触发一遍「空格变两个」，等于白重写。走的是一次性 `Input.insertText`（输入法上屏路径，`inputType` 仍是 `insertText`，不产生 `paste`），一次落一整行，编辑器没有插入两次的机会。

日志长这样：

```
  ⚠ 第 2 行不对，整行重写
    期望 │if·n·%·2·==·0:│
    实际 │if··n··%··2··==··0:│
  ✓ 第 2 行重写成功
```

结尾会汇总 `有 N 行打完当场对不上，已逐行重写修正`。只要看到这行且没报「重写后还是不对」，交上去的就是对的。

全部打完之后还会自动做一次**逐行比对**。对不上时**不会清空重来** —— 输进去的内容原样留着，日志会指出具体哪一行错、错多少个空格：

```
— 逐行对照（目标 4 行 / 实际 4 行）—
  第 4 行：缩进 0 个空格（应为 4，少了 4）
    目标 │····return·0│
    实际 │return·0····│
  → 汇总：缩进少了 1 行
  → 行首空格被编辑器吃掉了，点「修正缩进」可以补回来
```

`·` 就是空格，一行几个点就是几个空格，肉眼能数。

看到这种提示，点**「修正缩进」**即可。它做的事是：全选 → 回行首 → 逐行把行首空格调整到正确个数，正文一个字都不动。比清空重打快得多。

## 三个按钮怎么配合用

```
装完 → 体检（确认能找对编辑器）
  ↓
打一段 3 行的短代码试水
  ↓
跑完看日志：✓ 逐行比对通过 → 直接提交
  ↓
✗ 对不上 → 点「检视缩进」看是哪一行 → 点「修正缩进」
  ↓
还不行 → 清空代码区，把代码里的缩进改成 4 个空格的倍数再重来
```

## 三种速度

| 档位 | 平均间隔 | 100 行代码大约 | 适合 |
|---|---|---|---|
| 快速 | ×0.45 | 40 秒 | 赶时间，且确认平台不看速度 |
| 标准 | ×1 | 1 分 40 秒 | 默认 |
| 慢速 | ×2.1 | 3 分半 | 求稳 |

节奏不是固定间隔，是按字符类型变的：

- 普通字符 45–110ms
- 连续空格（缩进）压到 22–48ms，人会顺手带过
- 换行后停 180–420ms
- 每 40 个字符左右来一次 280–700ms 的长停，像在想下一行

这个分布是为了让时间戳看起来像人敲的，不是为了快。

## 装完先做这三件事

**第一件事：点「体检」**

日志会打出：

```
— 页面结构 —
  CodeMirror：有，实例可用（能准确读到全文）
  选中的编辑器：<textarea> .inputarea 0x0 在 CodeMirror 里
  实际接收键盘的元素：<textarea> .inputarea
  当前内容：0 字
```

如果显示 `选中的编辑器：（没找到）`，说明这个页面的代码区还没渲染出来，或者 PTA 换了实现 —— 把这几行发我。

**第二件事：拿一段 3 行的短代码试**

```
a = 1
b = 2
print(a + b)
```

跑完看编辑器里是不是正好三行。这是最省时间的验证，比拿 100 行去试快得多。

**第三件事：手动确认焦点**

点「开始输入」前，用鼠标点一下代码区。插件自己也会尝试聚焦，但页面拿不到焦点时点了也白点。

## 常见问题

**面板没出现**

刷新页面。还不行就去 `chrome://extensions/` 看插件有没有报错。

**浏览器顶部弹出「已开始调试此浏览器」黄条**

正常现象。CDP 需要挂上调试器才能发按键，输入结束会自动断开，黄条也就消失了。中途点黄条上的「取消」会让输入中断。

**输入到一半停了**

看日志最后一行。常见的是：

- `✗ 第 N 个字符发不出去：...` —— 调试权限被拒。关掉 F12 开发者工具再试
- `⚠ 点不进编辑器（focus 失败）` —— 先手动点代码区
- `⏹ 手动停止` —— 点了停止按钮

**字数对不上**

日志会打 `⚠ 已发 N 字，但编辑器里只有 M 字`，紧跟着的「逐行对照」会指出差在哪一行。已经打进去的内容会保留，不会被自动清掉。

**提交后报 IndentationError**

说明缩进和你的代码不一致。点「检视缩进」看具体哪行，`·` 的个数就是空格个数。再点「修正缩进」对齐。

如果修正后还是错，多半是代码里混了 Tab。这个插件统一按空格处理缩进 —— 把源码里的 Tab 全换成 4 个空格再贴进来。

**提交后判错**

插件只负责把字敲进去，不负责代码对不对。先在本地跑一遍。
